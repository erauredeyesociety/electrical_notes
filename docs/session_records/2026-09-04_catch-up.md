Apply the Catch Up directive to `/home/devel/electrical_notes`, under hard constraints:

## Why it was a bootstrap, not a catch-up

The Catch Up directive assumes prior structure that has drifted. There was none:

- `docs/` at the repo root was created **empty** minutes before this pass — eleven folders, zero files.
- The only root orientation was `README.md`, 130 bytes: *"Notes for classes, mostly AI generated"*.
- No `scope.md`, no `roadmap.md`, no `todo.md`, no directives, no `INDEX.md` anywhere.

So the prune passes the directive prescribes — `## Prune Documentation`, `## Prune Tests`, the folder
reshuffle — were **not run**. There was nothing accreted at the root to prune, and the accretion that
does exist lives inside course folders the operator ruled out of bounds. Pruning them would have been a
scope violation, not a cleanup.

## What was found

Ten items, full detail and paths in [../DRIFT_REPORT.md](../DRIFT_REPORT.md). The three that matter:

1. **A doctrine seam that closed underneath the report.** At 16:16 the shared toolchain duplicated a
   live course-local one: two definitions of `answerbox`, and `content/cesc_410/hw/prompt.md` — the file
   an agent actually enters through — never mentioned the repo-level directive. **By 16:26 another
   writer had migrated it**: all 7 `cesc_410` and 11 `cesc_470` problem files now input the shared
   preamble, and the old preamble is an explicit tombstone (*"SUPERSEDED — do not `\input` this file"*)
   with zero remaining references. § 2 of the drift report was **rewritten** to describe what is on disk
   rather than what was found. The residual gap is real and still open: **`content/cesc_470/hw/` and
   `content/cpsc_462/hw/` have no `prompt.md` at all**, and `cesc_470` already has eleven written problem
   files.
2. **Durable knowledge is sitting in root `tmp*.md`.** `tmp_ocr_child.md` holds the `/Ink`-object
   measurement that one side of an open `ocr_handler` contradiction depends on —
   `ocr_handler/docs/findings/INDEX.md` already cites it *by its root path* as a known misplacement.
3. **Nothing is checked before a push.** No local `hugo --minify` check, no LaTeX build in CI, and
   `hugo-version: latest` is unpinned — an upstream release can break the **public** site with no local
   change. The CI also runs `git submodule update` against a repo with no `.gitmodules` (the theme is a
   Hugo module).

Smaller but concrete: the landing page indexes **3 of 15** courses and 14 courses have no `_index.md`;
`scripts/` holds six files referenced from nowhere, one of which rewrites every `.md` in the repo in
place; `docs-rag/` is a 417-file child project with no bootstrap and no git tracking.

Two choices worth recording:

- **The empty INDEX files say *why* they are empty and where the equivalent content actually lives.**
  An index that just says "empty" teaches nothing; `findings/INDEX.md` instead points at the five in-tree
  conventions that hold this repo's real findings, and `lessons_learned/INDEX.md` names the three lessons
  that are already earned and only need distilling.
- **`testing-discipline.md` argues *against* a root `tests/persistent/`.** The root repo ships no
  application code; a unit-test folder would protect nothing. Its floor is three build checks. The child
  projects' real floors are named as protected.
